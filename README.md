# БарбарониТЕ – сайт + админ панел

Next.js 16 приложение за barbaronite.eu: публичният сайт се генерира от база данни (Neon Postgres) и се управлява от панел на адрес **/admin**.

Дизайнът на публичния сайт е пренесен от оригиналния статичен сайт – същите цветове (синьо `#0244ae`, светлосиньо `#96d5ff`, лилаво `#7021a3`), шрифт Montserrat Alternates, вълнистата линия под заглавията, „балонът“ бутон, картичките с разгъване при посочване и подредбата 3-2-2. Съдържанието (текстове, биографии, снимки, събития) е взето от старите HTML файлове и е заредено като начално съдържание в панела.

## Какво има вътре

| Раздел в панела | Какво управлява |
| --- | --- |
| Табло | Нови записвания и запитвания, предстоящи събития, последни действия |
| Записвания | Заявки от формата за записване – статус (ново / потвърдено / отказано), вътрешна бележка, CSV експорт |
| Запитвания | Съобщения от контактната форма – маркиране като обработени |
| Дейности | Курсовете: име, описания, лого, цвят, преподавател, формат, възраст, цена, подредба, видимост |
| Екип | Преподаватели: малка снимка (картичка) и голяма снимка (страница „За нас“), длъжност, биография |
| Програма | Сезони (само един е активен на сайта) и занимания по ден и час |
| Събития | Заглавие, подзаглавие (мото), дата, три снимки (галерия), описание с тематични седмици и т.н.; минават в „Отминали“ автоматично след крайната дата или ръчно |
| Новини | Публикации с чернова/публикувана |
| Текстове | Заглавия и въвеждащи текстове на всяка страница, текст в долната част |
| Снимки | Преглед и качване във вашия Cloudinary акаунт |
| Настройки *(само админ)* | Контакти, социални мрежи, имейл за известия, SEO |
| Потребители *(само админ)* | Неограничен брой потребители с роля „Администратор“ или „Редактор“ |
| Дневник *(само админ)* | Кой какво е променил |
| Моята парола | Смяна на собствената парола |

Публични страници: `/`, `/za-nas`, `/deynosti`, `/deynosti/[slug]`, `/programa`, `/sabitiya`, `/sabitiya/[slug]`, `/novini`, `/novini/[slug]`, `/kontakti`, `/zapisvane`. Старите адреси (`za-nas.html`, `what-we-do.html`, `program.html`, `summer-academy.html`, `contacts.html`) се пренасочват с 301 към новите, за да не се губят позиции в Google. Има `sitemap.xml` и `robots.txt`.

Публичните страници се кешират (ISR, 1 час) и се опресняват веднага при всяка промяна в панела – сайтът остава толкова бърз, колкото статичният.

## Пускане на Vercel – стъпка по стъпка

Сайтът работи на два етапа, за да не зависи от нищо допълнително:

1. **Без база данни** – веднага след качване на кода сайтът е на живо с началното съдържание (текстове, дейности, екип, събития от стария сайт). Панелът показва само инструкции на `/admin`.
2. **С база данни** – след добавяне на Neon (т. 3–5) панелът се включва и съдържанието се редактира оттам.

### 1. Кодът в GitHub

Качете всички файлове от проекта в repo-то `website_barbaronite` (branch `main` – това, което показва домейнът). Старите `.html`/`.css` файлове може да изтриете; ако останат, не пречат. **Не качвайте** `.env.local` – той е в `.gitignore`.

### 2. Vercel публикува сайта

Vercel прави deploy при всеки push. Проверете в *Settings → General*, че *Framework Preset* е **Next.js** (при статичен сайт може да е „Other“ – сменете го и направете *Redeploy*). Регионът на функциите е зададен във `vercel.json` на **fra1 (Frankfurt)**.

След deploy със статус *Ready* barbaronite.eu показва новия сайт. Старите адреси (`za-nas.html` и т.н.) се пренасочват автоматично.

### 3. База данни: Neon Postgres

В проекта във Vercel: *Storage → Create Database → Neon (Marketplace)* → *Continue*.

- **Region: Frankfurt (eu-central-1)** – същият като функциите.
- План: *Free* е достатъчен.
- *Connect to project* → Vercel добавя автоматично `DATABASE_URL`, `DATABASE_URL_UNPOOLED` и др. във всички среди.

Таблиците се създават автоматично при следващия deploy (`npm run build` изпълнява миграциите, когато има `DATABASE_URL`).

### 4. Променливи на средата

*Settings → Environment Variables* (за Production, Preview и Development):

| Променлива | Стойност |
| --- | --- |
| `AUTH_SECRET` | дълъг случаен низ, поне 32 символа (напр. генериран от https://generate-secret.vercel.app/48) |
| `CLOUDINARY_CLOUD_NAME` | `dk4bzhxfg` (вашият cloud name) |
| `CLOUDINARY_API_KEY` | от Cloudinary → *Settings → API Keys* |
| `CLOUDINARY_API_SECRET` | от същото място |
| `CLOUDINARY_FOLDER` | `barbaronite` (папка, в която панелът качва) |
| `RESEND_API_KEY` | от https://resend.com → *API Keys* (вижте т. 6) |
| `RESEND_FROM` | `БарбарониТЕ <onboarding@resend.dev>` докато домейнът не е верифициран; после напр. `БарбарониТЕ <noreply@barbaronite.eu>` |
| `NEXT_PUBLIC_SITE_URL` | `https://www.barbaronite.eu` |

### 5. Redeploy и първи администратор

*Deployments → последния deploy → Redeploy* (променените променливи важат от следващия deploy). След статус *Ready* отворете `https://www.barbaronite.eu/admin/setup`:

1. Въведете име, имейл и парола (мин. 10 символа).
2. Оставете отметката *„Зареди съдържанието от текущия сайт“* – същото съдържание, което сайтът показваше без база, влиза в базата и става редактируемо.
3. Натиснете *Създай администратор* – влизате директно в панела.

Страницата `/admin/setup` работи само докато няма нито един потребител. След това всички нови потребители се добавят от *Потребители → + Нов потребител*.

Формите за контакт и записване работят от момента, в който има база **или** Resend (т. 6); дотогава показват телефона и имейла за връзка.

### 6. Имейл известия (Resend)

Новите записвания и запитвания се записват в панела винаги. За да идват и по имейл на `info@barbaronite.eu`:

1. Регистрирайте се в https://resend.com **с имейла info@barbaronite.eu** и създайте API key.
2. Докато домейнът не е верифициран, Resend изпраща от `onboarding@resend.dev` **само до имейла на акаунта** – затова е важно акаунтът да е с info@barbaronite.eu.
3. За постоянна работа: *Domains → Add Domain → barbaronite.eu* и добавете дадените DNS записи (SPF, DKIM) при регистратора на домейна. След това сменете `RESEND_FROM` на `БарбарониТЕ <noreply@barbaronite.eu>`.

Имейлът-получател се сменя от *Настройки → Имейл за известия*.

### 7. Google

- `https://www.barbaronite.eu/robots.txt` и `https://www.barbaronite.eu/sitemap.xml` се генерират автоматично (sitemap-ът включва всички дейности, събития и новини и се обновява сам).
- Регистрирайте сайта в **Google Search Console** (search.google.com/search-console): *Add property → Domain → barbaronite.eu* → добавете дадения TXT запис в DNS на домейна. После *Sitemaps → добавете `sitemap.xml`*. Индексирането отнема от няколко дни до 2–3 седмици.
- За верификация по алтернативния начин (HTML файл): сложете файла в папката `public/` и го качете в repo-то – ще е достъпен на `https://www.barbaronite.eu/google….html`.

## Планове и лимити

- **Vercel Hobby** е безплатен, но условията му не позволяват комерсиална употреба. Ако сайтът се ползва за платени курсове, правилният план е *Pro* ($20/месец).
- **Neon Free**: 0.5 GB, автоматично „заспиване“ при бездействие и събуждане при първата заявка (~1 сек.). За този сайт е предостатъчно.
- **Cloudinary Free**: 25 GB трафик/месец – съществуващият акаунт вече е на този план.
- **Resend Free**: 3 000 имейла/месец.

## Роли

- **Администратор** – всичко, включително потребители, настройки и дневник.
- **Редактор** – съдържание (дейности, екип, програма, събития, новини, текстове, снимки), записвания и запитвания.

Единственият активен администратор не може да бъде деактивиран или понижен; никой не може да изтрие собствения си профил.

## Смяна на парола / забравена парола

Всеки сменя своята парола от *Моята парола*. Ако някой е забравил паролата си, администратор му задава нова от *Потребители → (име) → Нова парола*. Ако е забравена паролата на единствения администратор – вижте „Локална работа“ по-долу и задайте нова през `npm run db:studio` (таблица `users`, полето `password_hash` се генерира с bcrypt) или се обърнете към разработчика.

## Локална работа (за разработчик)

```bash
npm install
cp .env.example .env.local        # попълнете DATABASE_URL към локален Postgres или Neon
npm run db:migrate                # създава таблиците
npm run dev                       # http://localhost:3000, панел на /admin/setup
```

Полезни команди: `npm run db:studio` (визуален редактор на базата), `npm run db:generate` (нова миграция след промяна в `src/db/schema.ts`), `npm run typecheck`.

### Структура

```
src/
  content/seed.ts    началното съдържание – единственият източник и за базата, и за показване без база
  app/(site)/        публичните страници
  app/admin/(auth)/  вход и първоначална настройка
  app/admin/(panel)/ панелът (layout-ът проверява сесията)
  app/api/           подпис за Cloudinary, CSV експорт
  actions/           server actions – всички записи в базата минават оттук (валидация със zod)
  components/        UI компоненти за сайта и панела
  db/                Drizzle схема, връзка, начално съдържание
  lib/               auth (JWT бисквитка + bcrypt), data (достъп до базата с fallback без база), markdown, email, cloudinary
  proxy.ts           /admin → инструкции без база; → /admin/login без сесия
scripts/migrate.mjs  изпълнява миграциите само когато има DATABASE_URL
drizzle/             SQL миграции (изпълняват се при build)
```

### Технологии

Next.js 16 (App Router, Server Actions), Drizzle ORM + `pg`, Neon Postgres, Tailwind CSS 4, zod, bcryptjs, jose, Cloudinary SDK, Resend, marked + sanitize-html.

### Ако някога решите да смените базата

Кодът работи с всеки Postgres (Supabase, Railway, собствен сървър) – сменя се само `DATABASE_URL` (за Supabase ползвайте *pooled* връзката на порт 6543 за приложението и директната за `DATABASE_URL_UNPOOLED`).
